================================================================
构思技艺 (GS) —— 独立版安装说明
================================================================

本插件是**独立 jar 附属**，不再依赖 RykenSlimeCustomizer (RSC)。
装一个 jar 就能用。

----------------------------------------------------------------
一、前置条件
----------------------------------------------------------------

  1. 服务端 Paper 1.21.11（或同代 Paper 分支）
     ★ 低于 1.21.11 会因为缺材质 / 缺音效而出现丢包、特效消失等问题。

  2. 已安装 Slimefun4（粘液本体）
     ★ 本插件在 plugin.yml 里是 depend: [Slimefun]，本体不在就加载不起来。

  3. JDK 21 运行环境

----------------------------------------------------------------
二、安装（三步）
----------------------------------------------------------------

  1) 把 GS.jar 放进：
       <服务器根目录>/plugins/

  2) 确认服务器上**没有**旧的 RSC 版构思技艺附属。
     如果以前用过 RSC 版，请删掉：
       <服务器根目录>/plugins/RykenSlimeCustomizer/addons/GS/
     ★ 两版并存会重复注册物品（物品组里出现两套同 id 条目）。

  3) 重启服务器。

  首次启动会自动把内容解包到：
       <服务器根目录>/plugins/GS/content/

----------------------------------------------------------------
三、升级
----------------------------------------------------------------

  · 直接覆盖 plugins/GS.jar，然后重启。
  · plugins/GS/content/ 里的文件**只补不缺** ——
    你的改动不会被覆盖，新版本新增的条目会被补上。
  · ★ 从「内嵌 GraalJS 的旧版」升级上来的话，
    plugins/GS/lib/ 这个目录已经没用了，可以手动删掉
    （旧版用它装 15 个 GraalJS 运行库，共 70.8 MB）。
    留着不影响运行，只是白占空间。

----------------------------------------------------------------
四、命令
----------------------------------------------------------------

  /gs info      查看版本与上次加载统计（物品组 / 物品 / 机器 / 脚本模块数）
  /gs reload    重置配置缓存与脚本模块（重新注册监听器）
  /gs           等同于 /gs info

  权限：gs.command（默认 OP）

  ⚠️ /gs reload **不会**重读 items.yml / mb_machines.yml 等物品定义。
     原因：Slimefun 没有反注册 API，重读只会往注册表里塞同 id 副本。
     改物品 / 机器 / 配方请**重启服务器**。

----------------------------------------------------------------
五、启动成功的标志
----------------------------------------------------------------

控制台应出现（顺序也一致）：

  [GS]   构思技艺 (GS) 开始加载  ·  万物初生，始于想象
  [构思技艺] 梦境盔甲：致命伤害拦截已注册（同步监听器）
  ...
  [构思技艺] 借寿 已加载 · 沿准星三维朝向 长5×宽5×高2 ...
  [GS]   构思技艺 (GS) 加载完成  ·  用时 NNN ms
  [GS]     物品组 24 ｜ 配方类型 13 ｜ 菜单 7 ｜ 预加载 55 ｜ 物品 55
  [GS]     配方机器 4 ｜ 材料发生器 3 ｜ 多方块机器 1
  [GS]     脚本已 Java 化 18 个 ｜ 本次实际实例化 15 个
  [GS]   构思技艺 (GS) 加载成功！

  ★ 那一整段 `[构思技艺] ...` 共 85 行，
    与 RSC 参考服逐字节一致（由 tools/log_parity.py 机械对账）。

  ★ 「本次实际实例化 15 个」是**正常的**：
    18 个脚本模块里有 3 个（gs_guide_book / gs_info_creator /
    gs_update_log）只被物品组按钮引用，按需实例化 —— 与 RSC 行为一致。
    玩家第一次点「构思技艺图鉴」时，会打出一行：
      [构思技艺] gs_guide_book 已加载（19 页）

----------------------------------------------------------------
六、故障自检
----------------------------------------------------------------

  · 完全没有 [构思技艺] 日志
      → 看控制台有没有 [GS] 开头的行。没有的话说明本插件没被加载：
        检查 Slimefun4 是否在、jar 是否放对位置。

  · 报「加载失败 —— 详见上方堆栈」
      → 上方堆栈会指出是哪一类内容读挂了。

  · 物品全是「未知物品」/ 材质变成石头
      → plugins/GS/content/saveditems/ 缺文件。
        saveditems 是内容的一部分（头颅皮肤 / 纹饰这些组件写不进 items.yml），
        删掉它对应物品就会变空气或石头。删掉 plugins/GS/content/
        再重启可以重新解包。

  · 改完 items.yml 没生效
      → 需要重启服务器，/gs reload 不重读物品定义（见第四节）。

  · 物品组里出现两套同 id 物品
      → 旧 RSC 版附属还在，见第二节第 2 步。

----------------------------------------------------------------
七、本版与原 RSC 版的差异（都已机械核对）
----------------------------------------------------------------

  1. 全部 18 个 GraalJS 脚本已改写为纯 Java 模块。
     成品 jar 约 1.1 MB（原内嵌 GraalJS 版 34.8 MB），
     启动不再需要初始化 JS 引擎。

  2. ★ 修掉了一个真实缺陷：原脚本用 JS 的 double 去调 Java 的 float 形参
     （setRotation / setWalkSpeed / playSound 的音量音高等）时，
     GraalJS 会因为「精度损失」拒绝转换并抛异常，而脚本自己的
     try/catch 把它吞掉 ⇒ **这些调用一直是静默失效的**。
     受影响共 246 处（其中 120 处确定失效）。
     纯 Java 没有这层互操作边界 ⇒ 本版这些效果**按作者本意生效**：
       · 守夜人的视角锁定 / 拉人传送（原本 81/216 次失败）
       · 19 个音效里的 15 个（原本是哑的）
       · 各 boss 的朝向 / 音量 / 进度条
     ★ 这**不是**「顺手优化」，是按作者本意修复；用户已明确选择此方案。

  3. ★ 修掉了监听器泄漏：原脚本每次 /rsc reload 都会重新注册一遍监听器
     （脚本级闩锁 reload 后归零），导致概率类效果翻倍
     （例如某个 7% 会变成 14% / 21%）。本版改为幂等注册。

  4. ★ 补上了 /gs 命令的实现。原版 plugin.yml 声明了这个命令却从没注册
     executor，敲 /gs 会 NPE。

  5. 行为逐字保留：所有概率、数值、颜色码、物品 id、槽位号、tick 延迟
     都与原脚本一致（含原脚本里那个 `%s 已加载 · %s ` 的字符串拼接写法）。
