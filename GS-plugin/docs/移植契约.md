## 2. 六条转换纪律（踩过的坑，逐条都有实例）

1. **数值逐字**：JS 的 `0.7071` 就是 `0.7071`，别写成 `Math.sqrt(0.5)`。
2. **`try/catch` 对等**（见红线 2/3）。
3. **JS 浮点除法 vs Java 整除**：JS `(minX+maxX)/2` 是**浮点**；Java 里 `int` 相除会截断
   ⇒ 必须写 `/ 2.0`。**这是本项目踩过最多的坑**。
   （例外：已证明 `width` 恒为奇数时 `(width-1)/2` 两种语言**等价**，这种情况可以保留整除，
   但**必须在注释里写明证明**。）
4. **JS 动态派发 vs Java 静态类型**：JS 里 `e.addPotionEffect(...)` 能过，Java 里
   `addPotionEffect` 在 `LivingEntity` 上 ⇒ 需要显式 `((LivingEntity) e)`。
5. **lambda 捕获**：在 `catch` 块里赋值的局部变量**不是** effectively final
   ⇒ 要另起一个 `final` 局部变量（本项目在 `FakeWeisiModule` 踩过）。
6. **改完必须同时更新** `docs/阶段2迁移台账.md`（但如果你是被指派的子代理，把该行内容写进你的交付说明，由集成者统一改）。

### ★★★ 第 7 条：JS 的数字→字符串和 Java **不一样**（新发现的坑类）

凡是把**数字拼进日志行 / lore / 提示**的地方，都要小心。JS 的两个常用转换与 Java 的
同名/近名 API **语义不同**：

**① `Number.prototype.toFixed(f)`** —— 不是 Java 的 `String.format("%.2f")`

| 输入 | JS `toFixed` | Java `String.format("%.0f")` / `BigDecimal` 直觉 |
| --- | --- | --- |
| `(-2.5).toFixed(0)` | `"-3"` | `"-2"`（`HALF_EVEN`）或 `"-3"`（`HALF_UP`）—— 看用哪个 |
| `(-0.05).toFixed(0)` | `"-0"` | `"0"`（**丢了负号**） |
| `(-2.05).toFixed(1)` | `"-2.0"` | `"-2.1"`（若按 `Double.toString` 的 `-2.05` 舍入） |
| `(1.005).toFixed(2)` | `"1.00"` | `"1.01"`（同上） |

**正确语义**：对**精确二进制值**取绝对值后 **HALF_UP**，再补回符号（含负零特判）。
正确做法：
```java
BigDecimal bd = new BigDecimal(x);              // ★ 精确构造器，不是 BigDecimal.valueOf
bd = bd.abs().setScale(f, RoundingMode.HALF_UP);
if (bd.signum() == 0 && (Double.doubleToRawLongBits(x) < 0 || x < 0)) return "-0";  // 负零
return (x < 0 ? "-" : "") + bd.toPlainString();
```
★ **`BigDecimal.valueOf` 会走 `Double.toString`（最短表示）⇒ 不对**
（`-2.05` 的最短表示是 `-2.05`，但它的精确值是 `-2.0499999999999998223…`）。

**② `String(x)`** —— 不是 Java 的 `Double.toString(x)`

| 输入 | JS `String(x)` | Java `Double.toString(x)` |
| --- | --- | --- |
| `1000.0` | `"1000"` | `"1000.0"` ❌ |
| `4.9e-324` | `"5e-324"` | `"4.9E-324"` ❌ |
| `1e21` | `"1e+21"` | `"1.0E21"` ❌ |
| `-0.0` | `"0"` | `"-0.0"` ❌ |

**正确语义**：**最短可往返**十进制表示；指数 `k` 满足 `-6 ≤ k ≤ 21` 走普通记数法，
否则走指数记数法（**小写 `e`**、指数**带符号**、**无多余前导零**）；
`±0 → "0"`、`NaN → "NaN"`、`±Infinity → "±Infinity"`；整数值**不带 `.0`**。

**怎么发现这类问题**：写探针时，把「数字 → 字符串」的辅助函数**单独**在
**真 JS 的网格上逐字节对账**（`tools/PhantomParityProbe.java` 的 `[C]` 组就是这么做的：
47 个值 × 9 个精度位）。★ 现有日志大多只用正数的 `toFixed(1)`，踩不到边界 ——
**踩不到 ≠ 是对的**，边界值一改配置就会露出来。

**⚠️ 已知有 4 份拷贝**：`NbsSong` / `PhantomModule` / `CherrySub` / `PsychicSub`。
统一推广时按上面两条语义改写，并保留网格对账。

## 3. 死代码怎么办

**不要照抄走不到的分支**，但**必须在类注释里逐条写明**：
- 它是什么
- 为什么走不到（最好有实测证据）
- 删掉它为什么不改变可观察行为

已确认的死代码类型：
- GraalJS 25.1.3 里 **`JavaAdapter` 不存在**（`tools/GraalProbe.java` 实测）⇒ 所有
  `new JavaAdapter(...)` 退路都是死的。
- `Java.extend` 造 Runnable 的调度器退路（正路 `runLater` 实测可用）。
- 开关常量恒为 false 的函数体（如 `SG_CD_HINT = false` ⇒ 提示函数是空操作）。
- `Java.type('X')` 里 X 不存在 ⇒ 整个分支恒不执行。

### ★★★ 第 8 条：GraalJS 的 `double → Java float` 互操作**会静默失败**（影响 246 处）

**这是本项目发现的影响面最大的一条**，独立复核过（`tools/FloatInteropProbe.java`，`通过 7 ｜ 失败 0`）。

GraalJS 把 JS 的 `double` 塞进 Java 的 `float` 形参时，**只要该值不是 float 能精确表示的**，
就一律抛 `TypeError: Invalid or lossy primitive coercion`（方法重载解析失败时报
`no applicable overload found`）。而脚本自己的 `try { } catch (e) { }` 把它吞掉 ⇒ **该调用静默失效**。

实测（`tools/FloatInteropProbe.java`）：

| 调用 | 结果 |
| --- | --- |
| `setRotation(1.5, 0.0)` | ok（`1.5f == 1.5`） |
| `setRotation(1.1, 0.0)` | **抛**（`1.1f != 1.1`） |
| `setRotation(1.1, 0.0)` 给 **double** 形参 | ok ⇒ 问题确实出在 `float` 上，不是 JS 数值本身 |
| 真 `org.bukkit.Location#setRotation(1.1, 0.0)` | **也抛** ⇒ 真实 API 同样中招 |
| 先 `(float)1.1` 再传 | ok ⇒ 原脚本只要先转 float 就不会失效 |

`tools/audit_float_interop.py` 扫了全部 18 个脚本，共 **246 处**这类调用：
**120 处确定失效**（字面量如 `0.7 / 1.1 / 1.4`）、79 处几乎必然失效（参数是变量/表达式）、
仅 47 处原本生效。受害最重：致万千无言者 34 处、月镰 19 处、守夜人 15 处、幻影 14 处、
`gs_listener` 23 处、骑士 9 处。

受影响的形参：`Location` 的 yaw/pitch、`setRotation` / `setYaw` / `setPitch` /
`setWalkSpeed` / `setFlySpeed` / `playSound` 的音量与音高 / `BossBar#setProgress` 等。

**★ 本项目的处置（用户已明确选择「按作者本意修复」）**：
纯 Java 里**没有这层互操作边界** —— 写 `playSound(loc, s, 0.8f, 1.4f)` 就是普通 float，
不会抛；传 double 给 float 形参 Java 也只是**静默窄化**。
⇒ **机械移植的自然结果就是「修复后」的行为**，无需任何额外动作。
已核实**没有任何模块刻意复刻这个缺陷**（grep 全仓无 `isFloatExact` / `lossy` 之类的模拟代码）。
例外只有守夜人：它的作者当时**主动**做了判定，已在 `NightwatchModule` 里按「本意」实现，
探针 `[C9]` 把两侧行为都钉住了。

> ⚠️ **反向提醒**：正因为 Java 会**静默窄化**，从 Java 改回 JS 或写新的 JS 绑定时，
> 这类调用会**从「能跑」变成「静默失效」**，而且**不报错**。
> 排查手法：`tools/audit_float_interop.py`。

### ⚠️⚠️ 判「方法不存在」时必须用**编译器**，不能用 `javap`

**踩过的坑（代价：误删了 3 处生效的调用）**：某次用
`javap -cp paper-api.jar org.bukkit.entity.WitherSkull` 看不到 `setDirection`，
就判定「`Entity` 上没有 `setDirection`、原脚本那两句恒抛异常、是从未生效的死路径」，
于是**没移植**。

**这是错的**。原因：

> **`javap` 对一个接口/抽象类只列它自己声明的方法，不列继承来的。**
> `WitherSkull extends Fireball`，而 `Fireball` 声明了 `setDirection(Vector)`
> ⇒ `WitherSkull` **有**这个方法，但 `javap WitherSkull` 看不见。

**正确做法：写一个几行的类，拿真 paper-api 编译一次。能编译过 = 方法存在。**

```java
static void a(WitherSkull sk, Vector v) { sk.setDirection(v); }   // ✅ 通过
static void b(Trident   t,  Vector v) { t.setDirection(v); }      // ❌ 找不到符号
```

实测结论（paper-api 1.21.11）：`setDirection` 在 **`Fireball` 族**
（`Fireball` / `SmallFireball` / `DragonFireball` / `LargeFireball` / `WitherSkull`）上**存在**，
只在 **`Trident` / `Arrow` / `Projectile`** 上不存在。

**并且要看清调用点的「运行期实际类型」**：原脚本的
`try { pr.setDirection(...); } catch (e) { }` 里，`pr` 可能是**通用发射器**的返回值，
类型取决于入参。这时 Java 侧的正确等价物是
`if (x instanceof Fireball) ((Fireball) x).setDirection(v);`
—— `instanceof` 就是那个 `try/catch` 的**静态化**，语义逐字等价。

> ★ 教训：**「我查过了」不等于「我查对了」**。工具的适用范围本身要先验证：
> 用一个「已知有该方法」的对照组去试 `javap`，就不会得出「不存在」的错误结论。
> 这个项目里判「某 API 在 1.21.11 上到底有没有」，**一律以编译器为准**。

## 5. 模块骨架

```java
package com.qinghuacisj.gs.script.module;

/** {@code gs_xxx.js} 的 Java 化版本 —— 「显示名」。 …类注释写全：玩法、参数、死代码… */
public final class XxxModule extends AbstractModule {

    // ---- 参数：名字必须与 JS 顶层 var 同名（常量对账探针按名字反射比对）----
    static final String XX_ITEM_ID = "GS_XXX";
    static final double XX_DMG = 17.0;
    // …

    // ---- 运行期状态：**非静态**（实例 = 原脚本的一次顶层求值）----
    private final Map<String, Long> last = new HashMap<>();

    public XxxModule() {
        // ★ 构造器 = 原脚本的**顶层代码**（日志、注册监听器等）
        try {
            Bukkit.getLogger().info(loadLine());
        } catch (Throwable ignored) {
            // 与原脚本一致：静默
        }
    }

    @Override
    public String name() {
        return "gs_xxx";      // ★ 必须与 Modules 登记名、脚本文件名一致
    }

    @Override
    protected Object onUse(PlayerRightClickEvent event, Object reader) {
        // …
        return null;
    }
}
```

**关键语义**（`Modules.acquire` 用 `computeIfAbsent`）：
- **模块构造器 = 原脚本顶层代码**（急切求值、只跑一次）
- **模块成员字段 = 原脚本顶层变量**（同一脚本的两个引用点共享同一份全局状态）

`AbstractModule` 已支持的钩子：`init` / `onUse` / `onWeaponHit` / `onToolUse` /
`onButtonGroupClick` / `onPlayerJoin` / `onPlayerQuit` / `onPlayerDeath` / `onEntityDamage`。
**如果你的脚本用到别的钩子（如 `onPlayerInteract`），要在交付说明里明确指出** —— 那需要改
`AbstractModule`（共享文件），由集成者来做。

## 6. 编译与自测（**不要跑 `build.ps1`**）

5 个人同时跑 `build.ps1` 会互相覆盖 `build/classes`。所以：

```powershell
$JH = 'C:\Program Files\Microsoft\jdk-21.0.7.6-hotspot'
Set-Location 'D:\qq下载\粘液科技自用\GSPlugin'
$cp = ((Get-ChildItem libs -Filter *.jar | % FullName) -join ';') + ';' +
      ((Get-ChildItem libs\graal -Filter *.jar | % FullName) -join ';') + ';build\classes'

# 编译你的模块到你自己的输出目录
& cmd /c "`"$JH\bin\javac.exe`" -encoding UTF-8 --release 21 -nowarn -proc:none -cp `"$cp`" -d build\sub_xxx src\main\java\com\qinghuacisj\gs\script\module\XxxModule.java 2>&1"

# 编译并运行你的探针
& cmd /c "`"$JH\bin\javac.exe`" -encoding UTF-8 --release 21 -nowarn -proc:none -cp `"$cp`;build\sub_xxx`" -d build\sub_xxx tools\XxxParityProbe.java 2>&1"
& cmd /c "`"$JH\bin\java.exe`" -Dpolyglot.engine.WarnInterpreterOnly=false -Dstdout.encoding=UTF-8 -cp `"$cp`";build\sub_xxx com.qinghuacisj.gs.script.module.XxxParityProbe > build\xxx.txt 2>&1"
Get-Content build\xxx.txt -Encoding utf8
```

⚠️ PowerShell 陷阱（本机实测）：

- `java` 的 `-Dxxx` 参数**直接写在 PowerShell 里会被拆坏** ⇒ 一律走 `cmd /c "..."`。
- 中文输出：加 `-Dstdout.encoding=UTF-8`；读文件用 `Get-Content -Encoding utf8`。
- **不要把 java 的 stdout 通过 PowerShell 管道看**（会丢字符）；**重定向到文件再读**。

## 7. 探针（**必交**，这是"机械证据"）

写 `tools/XxxParityProbe.java`，`public static void main`，最后必须打印
**一行** `通过 N ｜ 失败 M`（集成者靠这行汇总），失败时 `System.exit(1)`。

必须包含这几类断言（**按需扩展，但不能少于**）：

1. **常量对账**：用 **真 GraalJS** 跑原脚本，读出顶层 `var`，
