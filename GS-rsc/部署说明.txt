★ 部署步骤（三步，务必按顺序）

1) 先删掉服务器上旧的附属文件夹：
     <服务器根目录>/plugins/RykenSlimeCustomizer/addons/GS/

2) 把本压缩包里的 **GS 文件夹整个**放进：
     <服务器根目录>/plugins/RykenSlimeCustomizer/addons/

   放好之后必须是这个结构：
     addons/GS/items.yml
     addons/GS/mb_machines.yml
     addons/GS/recipe_machines.yml
     addons/GS/scripts/gs_listener.js
     ...

   ⚠ 本版本**已删除 workbenches.yml**（织梦机整机移除），清单里不要再找它。
   ⚠ 本版本**已删除 scripts/gs_wb_debug.js**（织梦机专用的临时排查脚本）。

   ⚠⚠ 最常见的错误：把 GS 文件夹丢进了已经存在的 GS 文件夹里，
      变成 addons/GS/GS/items.yml —— 这样 RSC 读的还是上一层那份旧文件，
      表现就是"改了配置但游戏里完全没变化"。

3) 重启服务器，或执行 /rsc reload

★ 容易搞混的一点：旧物品不会自动更新

粘液物品的「材质 / 名字 / lore / 分类」是在**物品生成那一刻**写进物品数据里的。
所以改了 items.yml 之后：
  · 新产出的物品（/sf give、机器产出、按钮发放）→ 是新外观
  · 已经拿在玩家手上 / 放在箱子里的旧副本  → 永远保持旧外观，重启也不会变

⇒ 凡是被**整件删除**的物品（构念 / 颅咒跃 / 乐山乐水 / 狼王 / 豪到你了？ /
  空间割裂机 / 冰 / 智能附魔台 / 二极心象锻造仪 / 律师函 等），
  老存档里剩下的那些会变成**「未知物品」**（名字与 lore 全部消失）
  ⇒ **直接丢掉即可**，它们已经没有任何脚本响应。
  换了 ID 的物品同理（旧 ID 那一份变成未知物品）。

  ⚠ 反过来说：**改数值 / 改 lore 不会修好旧物品**。
    要看到新外观，必须让服务器**重新产出**一件（`/sf give` 或机器再合成一次）。
    图鉴成书也一样 —— **旧书不会自动更新**，要重新点一次领书按钮。
